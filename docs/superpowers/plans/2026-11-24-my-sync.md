# Synchronisation Hub vers my - Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un bouton admin "Envoyer sur my" qui, pour un projet Hub terminé, crée l'activité et la session sur my, inscrit et marque présents les membres, puis ajoute credits x 4 points à chacun dans Student Engagement.

**Architecture:** Un client HTTP my mince (`myClient`) et un service d'orchestration reprenable (`mySyncService.runSync`) qui écrit sa progression sur le `Project` après chaque appel réussi. Une route admin synchrone `POST /api/projects/:id/sync-my` avec verrou atomique. Une carte d'état sur la page admin du projet.

**Tech Stack:** Node/Express/Mongoose, axios 0.27, Jest + supertest + mongodb-memory-server, Next.js 12 (pages router), Tailwind avec tokens de design du repo.

**Spec:** `docs/superpowers/specs/2026-11-24-my-sync-design.md`

## Global Constraints

- API my : base `https://my.epitech.eu/api`, en-tête `Authorization: Bearer <MY_API_TOKEN>`. Spec OpenAPI : `https://my.epitech.eu/api/docs-json`.
- Login my = email de l'étudiant, comparé en minuscules.
- Points ajoutés par étudiant = `project.credits * 4`. Critère 5833 de la grille 1295 : une seule note cumulative, valeurs 0 à 16 (`MY_MAX_ENGAGEMENT_MARK`). `PUT .../assessments` remplace la note ET les commentaires : toujours renvoyer `individualComment`/`groupComment` lus juste avant.
- Ne JAMAIS appeler `/evaluations/assessments/session/{id}/confirm`.
- Variables d'environnement serveur : `MY_API_URL` (défaut `https://my.epitech.eu/api`), `MY_API_TOKEN`, `MY_HUB_UNIT_INSTANCE_ID` (949), `MY_ENGAGEMENT_PROJECT_ID` (5651), `MY_ENGAGEMENT_ACHIEVEMENT_ID` (5833), `MY_SCHOOL_YEAR` (2026), `MY_MAX_ENGAGEMENT_MARK` (16). Valeurs lues à l'appel, pas au chargement du module. Jamais dans le repo ni dans les logs.
- Durée de session : 30 minutes. Nom d'activité et titre de session : `Projet HUB - <nom du projet>`.
- Éléments du repo : `asyncHandler`, `ErrorResponse`, `authenticateToken` + `isAdmin`, `PROJECT_STATUSES` (`server/src/utils/constants.js`), `process.env.FRONTEND_URL`.
- Client : `useApi` ne mémorise pas `get` (jamais dans les deps d'un `useEffect`), tokens de design et dark mode existants, textes en français.
- Commits : texte brut, pas de `Co-Authored-By`, pas d'emoji (règle de l'utilisateur). Dans un worktree, utiliser `/usr/bin/git` (le hook rtk réécrit `git`).
- Frontend : tester uniquement via Docker (Node 25 casse Next.js 12 sur l'hôte), jamais `npm run dev` ni `next build` sur l'hôte.
- Tests serveur : `cd server && npx jest <chemin>`. Les tests ne doivent jamais appeler le vrai my (client simulé).

## Review Focus

Entrées ou pannes que la spec implique sans les nommer, les plus probables d'abord. Chacune a son test dans la tâche indiquée.

1. Étudiant déjà à 12 points sur my et projet à 2 crédits (12 + 8 = 20 > 16) : cet étudiant est en erreur, rien n'est écrit pour lui, les autres membres continuent (Tâche 4).
2. Crash après le `PUT` des points mais avant l'enregistrement : la reprise ne rajoute pas les points une seconde fois (Tâche 4).
3. Un membre dont l'email n'existe pas côté my (ou sans inscription à Student Engagement) : erreur sur lui seul, statut `partial`, les autres sont traités (Tâche 4).
4. Clé API expirée ou invalide (401 de my) : message explicite, état déjà enregistré conservé, `status` `partial` ou `idle`, pas de 500 brut (Tâche 5).
5. Double clic sur le bouton : le second appel obtient 409 et une seule activité existe (Tâche 5).
